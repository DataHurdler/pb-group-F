typing a long prompt from a printout wastes the time the day is built to save.

## Two kinds of prompt

| Kind | ID | What it's for |
| --- | --- | --- |
| **Practice** | P | Prompts learners run to practise a skill, often as a weak/strong pair so they can see the difference |
| **Test** | T | Prompts that test something. **Behaviour tests** show how ChatGPT behaves (does it admit what it doesn't know?). **Check prompts** test an output (does every figure trace to the source?). **Test inputs** test a learner's prompt (does it still work on a messy email, or when facts are missing?) |

Practice builds the skill. Testing is how learners find out whether the skill
worked, and it's what separates a prompt you can rely on from one that worked
once.

## How to test a prompt

Taught at the start of Block 6 and used informally in Blocks 3–5. It's also on
the [prompt checklist](../materials/handouts/prompt-checklist.md).

1. **Write pass criteria before you run it**: three to five things someone else
   could check. "Every agenda item has an owner." Not "it's good."
2. **Run it on a normal input.**
3. **Run it on a messy input**: long, rambling, badly organised.
4. **Run it on an input with facts missing.** A good prompt produces [CHECK];
   a weak one invents.
5. **Run it twice in new chats.** Is the variation acceptable for this task?
6. **Change one thing at a time** when it fails, and re-run the same tests.

## Conventions

- `[SQUARE BRACKETS]` mark what to replace.
- Every check prompt is a second pair of eyes, never the last one. ChatGPT can
  miss its own errors, or report errors that aren't there. **The learner does
  the final check against the source.**
- Run each prompt in a **new chat** unless it says otherwise. Earlier
  conversation steers the answer.
